## LitePPTX 1.8.0: Faster to open, lighter on memory

The speed release: nothing looks different, because nothing about the app changed — it just opens big decks near-instantly and uses far less memory doing it. Still zero dependencies, still tiny.

### What got faster

- **Opening a presentation.** A deck used to parse every slide before showing the first one. Now it reads only the slide list up front, and each slide is parsed when you first scroll to it, search it or export it. A 50-slide file opens near-instantly.
- **Rendering while scrolling.** Rendered slides now reuse bitmaps from a small pool instead of allocating a fresh frame for every scroll step. Flat slides — solid colours and text, no photos or gradients — render in 16-bit colour, which is half the memory with identical pixels. Photos and gradients still get full colour, so nothing bands or washes out.
- **Global search.** The first search of a file extracts its text; later searches reuse it. The cache is keyed by the file's size and last-modified time, so an edited file is re-read. Repeat searches are now free.
- **Starting the app.** The update check waits until the first screen is up instead of running during startup, and the housekeeping (update cleanup, stale cache files) moved off the start path.

### Technical

- `PptxParser.parse()` returns a `Deck` whose slides are an `AbstractList` backed by a loader lambda, with a small access-order cache of the last 8 parsed slides and a blank-slide fallback so a failed slide never breaks indexing.
- `Dom.parse` now takes an `InputStream` and streams through `XmlPullParser`; the `ByteArray` overload and both `readBytes()` call sites are gone.
- `SlideRenderer.render()` takes an optional reusable bitmap and picks RGB_565 only when the slide has no pictures, no gradients and no semi-transparent colours; the pool lives in `SlideAdapter` (cap 3, main thread only, never a bitmap a visible row is still showing).
- New `SearchCache` (in-memory LRU, 24 files / 2M characters, fingerprinted by size + last-modified; files without a last-modified stamp are never cached).
- Startup timing is logged to logcat under the `LitePPTX` tag — `onCreate total`, `first deck shown`, `recents rendered` — so the speedup can be measured on a real device with `adb logcat -s LitePPTX`.
- No new permissions, no new libraries, no androidx, no `java.time`. No new user-visible strings, so English and Persian stay in parity.

### Limitations (honest)

- Time-to-first-slide and peak memory still need a real-device measurement; the log lines above are there to make it possible.
- Global search hits on PPTX files still jump one slide too far and label one slide too high — a pre-existing v1.7.0 off-by-one, kept as-is in this release and to be fixed separately.
- Legacy `.doc`/`.ppt`/`.xls` are text-only; charts/SmartArt are still not rendered.
- Lossless PDF compression only works on classic xref-table PDFs. Most PDFs from scanners and office apps qualify; PDFs with object streams fall back to the rendered rebuild.
- The rendered rebuild turns pages into images, so text can no longer be selected or searched.
